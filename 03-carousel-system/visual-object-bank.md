# Visual Object Bank

## Purpose of this file
Use this file to choose visual objects, visual moves, consulting-style structures, and performance functions for argument-led carousels.

The visual system must explain the thinking, not decorate the slide.

## Core distinction
### Visual object
The recurring object or structure that helps the reader understand the idea, such as a decision tree, proof stack, evidence bank, or operating map.

### Visual move
The role a visual plays in the argument, such as creating tension, showing evidence, comparing weak versus strong behavior, revealing a mechanism, or giving a decision tool.

### Consulting-style structure
A structured analytical format borrowed from business thinking, such as a 2x2 matrix, waterfall, issue tree, driver tree, funnel, heatmap, or maturity curve.

### Performance function
The platform action the visual helps create, such as stopping power, swipe-through, saves, shares, comments, profile visits, or bio clicks.

## Selection rule
One carousel should have one central argument, but it may use multiple visual moves to develop that argument.

A carousel should not repeat the same visual object unless each repetition reveals a new layer of reasoning.

If the idea needs many unrelated visual systems to work, the idea is probably too broad. If the same visual repeats with only different wording, the carousel is probably too thin.

## Visual moves and when to use them
| Visual move | Intellectual function | Performance function |
| --- | --- | --- |
| Tension visual | Names a problem the audience has felt but not framed. | Creates stopping power. |
| Root-cause map | Shows why the problem exists structurally. | Creates swipe-through because the reader wants the diagnosis. |
| Evidence card | Grounds the argument in data, research, example, benchmark, or observed pattern. | Builds trust and save value. |
| Antithesis table | Shows default vs high-leverage behavior. | Creates shareability because readers recognize themselves or their workplace. |
| Leakage map | Shows where value, clarity, trust, proof, or decision quality disappears. | Creates saves because the reader can reuse the diagnostic lens. |
| Mechanism diagram | Explains the hidden process behind the problem. | Creates retention and saves. |
| Framework model | Gives the reader a reusable way to think. | Creates saves and profile visits. |
| Applied example | Runs a real work situation through the model. | Builds trust and reduces abstraction. |
| Decision tool | Helps the reader choose, prioritize, or act. | Creates saves and profile visits. |
| Behavior checklist | Turns the argument into operating behavior. | Creates saves and final-slide clarity. |
| Profile-entry slide | Connects the behavior shift to the category promise. | Creates profile visits and optional bio clicks. |

## Consulting-style structures
### 2x2 matrix
- **Use when:** The argument compares two drivers, such as visibility vs proof or automation speed vs process clarity.
- **Intellectual function:** Clarifies tradeoffs and reveals better positioning.
- **Performance function:** Creates saves because the reader can place themselves or their team in a quadrant.
- **Avoid when:** The two axes are vague or invented after the fact.

### Waterfall
- **Use when:** The argument shows value leakage from work to outcome to proof to decision.
- **Intellectual function:** Shows how value changes across stages.
- **Performance function:** Creates saves because the loss pattern becomes easy to remember.
- **Avoid when:** There is no cumulative gain or loss to explain.

### Funnel
- **Use when:** The argument shows filtering from many inputs to fewer decisions, signals, or actions.
- **Intellectual function:** Shows narrowing, qualification, or prioritization.
- **Performance function:** Creates saves when it becomes a reusable decision screen.
- **Avoid when:** The process is not sequential or narrowing.

### Issue tree
- **Use when:** The argument breaks a messy problem into root causes or decision branches.
- **Intellectual function:** Separates symptoms from causes.
- **Performance function:** Creates profile visits when the reader wants more structured problem-solving.
- **Avoid when:** The branches are merely categories, not causes.

### Driver tree
- **Use when:** The argument connects outcomes to controllable inputs.
- **Intellectual function:** Shows what actually moves a result.
- **Performance function:** Creates saves for operators who need a reusable operating view.
- **Avoid when:** The drivers cannot be acted on.

### Antithesis table
- **Use when:** The argument needs weak vs strong operator contrast.
- **Intellectual function:** Shows default vs high-leverage behavior.
- **Performance function:** Creates shareability because readers recognize themselves or their workplace.
- **Avoid when:** It shames the reader instead of upgrading their lens.

### Leakage map
- **Use when:** The argument explains where work loses value, proof, clarity, attention, or decision usefulness.
- **Intellectual function:** Makes invisible failure points visible.
- **Performance function:** Creates saves and comments because it explains a familiar frustration.
- **Avoid when:** The map only labels steps without showing leakage.

### Operating model map
- **Use when:** The argument explains how people, inputs, decisions, rhythms, and outputs should connect.
- **Intellectual function:** Shows how work should function as a system.
- **Performance function:** Creates profile visits from readers who want operating systems.
- **Avoid when:** The topic is a single habit or one-time communication problem.

### Maturity curve
- **Use when:** The argument shows progression from weak to strong operator behavior.
- **Intellectual function:** Helps the reader locate their current level and next upgrade.
- **Performance function:** Creates saves and shares because people compare where they or their team sit.
- **Avoid when:** The stages are arbitrary.

### Proof trail
- **Use when:** The argument explains how work becomes evidence over time.
- **Intellectual function:** Shows the path from action to outcome to proof to decision.
- **Performance function:** Creates saves and product intent for proof-related assets.
- **Avoid when:** The idea is not about visibility, trust, appraisal, updates, or credibility.

### Decision tree
- **Use when:** The audience needs a sequence of if/then decisions.
- **Intellectual function:** Clarifies choices under uncertainty.
- **Performance function:** Creates saves because it becomes a practical tool.
- **Avoid when:** The problem is about evidence, rhythm, or narrative rather than choice.

### Heatmap
- **Use when:** The argument compares intensity, risk, ambiguity, or priority across areas.
- **Intellectual function:** Shows where attention should go first.
- **Performance function:** Creates saves and comments when readers can diagnose their own situation.
- **Avoid when:** The scoring logic is unclear.

### Evidence card
- **Use when:** The argument needs research, a credible statistic, a mini-case, benchmark, or observed pattern.
- **Intellectual function:** Supports the claim with proof.
- **Performance function:** Builds trust and increases saves/shares.
- **Avoid when:** The evidence is unrelated, vague, invented, or decorative.

### Root-cause map
- **Use when:** The argument must explain why the problem exists structurally.
- **Intellectual function:** Moves the reader from symptom to cause.
- **Performance function:** Creates swipe-through because readers want the deeper explanation.
- **Avoid when:** It only lists complaints.

### Profile-entry slide
- **Use when:** The final slide needs to connect behavior shift to the category promise.
- **Intellectual function:** Converts insight into a next operating lens.
- **Performance function:** Creates profile visits and, where relevant, bio clicks.
- **Avoid when:** It becomes aggressive selling or unrelated CTA copy.

## Core visual objects
### Decision tree
- **Explains best:** How to choose between paths under uncertainty.
- **Best-fit pillars:** Strategy Systems, Corporate Leverage, Capital & Narrative.
- **Use when:** The audience needs a sequence of if/then decisions.
- **Do not use when:** The problem is about evidence, rhythm, or narrative rather than choice.

### Control panel
- **Explains best:** The few signals an operator should monitor to run a system.
- **Best-fit pillars:** Founder Leverage, Corporate Leverage, Strategy Systems.
- **Use when:** The problem is recurring and needs ongoing operating visibility.
- **Do not use when:** The idea is a one-time decision or narrative teardown.

### Evidence bank
- **Explains best:** How to collect proof of work, progress, or impact.
- **Best-fit pillars:** Corporate Leverage, Capital & Narrative.
- **Use when:** The audience needs to make invisible work visible.
- **Do not use when:** The problem is primarily about choosing between options.

### Proof stack
- **Explains best:** How different layers of proof build trust.
- **Best-fit pillars:** Capital & Narrative, Founder Leverage, Corporate Leverage.
- **Use when:** The audience needs to turn traction, work, or claims into credible evidence.
- **Do not use when:** The problem is a simple workflow or checklist.

### Narrative spine
- **Explains best:** The logic that connects context, change, evidence, and ask.
- **Best-fit pillars:** Capital & Narrative, Corporate Leverage.
- **Use when:** The issue is communication clarity, not execution mechanics.
- **Do not use when:** The idea is mainly about operations or metrics monitoring.

### Operating map
- **Explains best:** How work flows across people, inputs, decisions, and outputs.
- **Best-fit pillars:** Strategy Systems, Founder Leverage, Corporate Leverage.
- **Use when:** The audience needs to see how a system works end to end.
- **Do not use when:** The idea can be explained with a simpler scorecard or decision tree.

### Scorecard
- **Explains best:** How to evaluate quality, readiness, maturity, or fit.
- **Best-fit pillars:** Strategy Systems, Corporate Leverage, Founder Leverage.
- **Use when:** The reader needs to assess a current state.
- **Do not use when:** The argument requires sequencing rather than evaluation.

### Ladder
- **Explains best:** Progression from lower-leverage to higher-leverage behavior.
- **Best-fit pillars:** Corporate Leverage, Founder Leverage.
- **Use when:** The post shows maturity or capability development.
- **Do not use when:** The stages are arbitrary.

### Loop
- **Explains best:** Recurring behavior, feedback, or review rhythms.
- **Best-fit pillars:** Founder Leverage, Strategy Systems, Corporate Leverage.
- **Use when:** The problem repeats because there is no operating rhythm.
- **Do not use when:** The issue is a one-time decision.

### Decision layer
- **Explains best:** The difference between data, interpretation, options, tradeoffs, and action.
- **Best-fit pillars:** Strategy Systems, Corporate Leverage.
- **Use when:** The audience is confusing reporting with decision-making.
- **Do not use when:** The issue is mostly emotional motivation or personal productivity.

### Visibility panel
- **Explains best:** How to make contribution, progress, and impact legible to stakeholders.
- **Best-fit pillars:** Corporate Leverage, Founder Leverage.
- **Use when:** The audience needs structured proof without bragging.
- **Do not use when:** The problem is about investor narrative or GTM logic.

### Work-to-impact chain
- **Explains best:** How activities connect to outcomes, proof, and strategic value.
- **Best-fit pillars:** Corporate Leverage, Strategy Systems, Capital & Narrative.
- **Use when:** The audience needs to show why work mattered.
- **Do not use when:** The idea is only about organizing tasks.

## Final visual selection test
Before choosing a visual, answer:

1. What is the central argument?
2. What does this visual reveal that the headline cannot?
3. Does the visual show structure, causality, contrast, decision logic, or value leakage?
4. What intellectual function does it serve?
5. What performance function does it support?
6. Will repeating the object reveal new reasoning, or only new wording?
