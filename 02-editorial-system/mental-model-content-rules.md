# Mental Model Content Rules

## Purpose of this file
Use this file to approve or reject free content ideas before they become carousel briefs.

## Required structure for every free post
Every mental-model-led post should include:

1. **Real operator problem** — the messy work situation the audience recognizes.
2. **Hidden thinking flaw** — the incorrect assumption, missing layer, or poor framing causing the problem.
3. **Mental model** — the reusable way to think about the issue.
4. **Visual explanation** — a map, scorecard, decision tree, control panel, evidence bank, or other central visual object.
5. **Small applied example** — a simple example showing how the model changes the work.
6. **Optional paid asset bridge** — only if the paid asset helps implement the model faster.

## Editorial rules
- Start with the work problem, not the tool.
- Teach the thinking before mentioning implementation.
- Make the hidden flaw specific enough to feel diagnostic.
- Use one clear mental model per post.
- Keep examples practical and operator-grade.
- Keep AI as leverage, not decoration.
- Separate free teaching from paid implementation.

## What this prevents
- Generic listicles
- Generic AI tips
- Tool-first tutorials
- Prompt dumps
- Text-heavy advice posts
- Motivation without method
- Founder hustle content
- Corporate jargon without operator utility

## Quality test
Approve an idea only if it passes most of these questions:

1. Does it begin with a real operator pressure?
2. Is there a hidden thinking flaw, not just a surface complaint?
3. Can the mental model be reused in more than one situation?
4. Can the idea be explained visually with one central object?
5. Would the post still work if no tool was named?
6. Does the free version improve thinking, diagnosis, communication, or decision quality?
7. If there is a paid bridge, does it offer implementation speed rather than more generic advice?

## Rejection rule
If the idea cannot be turned into a clear mental model and visual object, reject or reframe it before writing.
