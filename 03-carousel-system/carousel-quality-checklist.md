# Carousel Quality Checklist

## Purpose of this file
Use this as the strict approval checklist before a carousel moves from brief to design or publishing.

## Pass/fail checklist

### Mental-model-led
- [ ] The carousel teaches one reusable mental model.
- [ ] The model improves thinking, diagnosis, communication, or decision quality.
- [ ] The idea would still work if no AI tool was mentioned.

### Operator-problem-led
- [ ] The carousel starts with a real operator pressure.
- [ ] The audience problem is specific, not generic productivity pain.
- [ ] The hidden thinking flaw is clearly named.

### Visual-first
- [ ] There is one central visual object.
- [ ] The visual explains the idea rather than decorating it.
- [ ] The carousel feels like an operating diagram, not a text slideshow.

### Low-text
- [ ] Each slide has one idea.
- [ ] Slide copy uses short labels or sharp sentences.
- [ ] No slide depends on paragraphs to make sense.

### Tool-secondary
- [ ] Tools are not the hook.
- [ ] ChatGPT, Codex, Notion, Sheets, n8n, Razorpay, or other tools appear only as implementation layers if mentioned.
- [ ] The post is not a tool tutorial in disguise.

### Non-generic
- [ ] The angle could not belong to any generic AI automation page.
- [ ] The tone is practical, sharp, calm, and operator-grade.
- [ ] The carousel avoids hype, hustle, and shortcut claims.

### Paid bridge clarity
- [ ] Any paid bridge is optional.
- [ ] The free post fully teaches the mental model.
- [ ] The paid bridge offers implementation speed, not secret knowledge.

## Red flags: reject or rework
Reject or rework the carousel if:

- The hook is mainly a tool name.
- The carousel is a listicle with design applied.
- The visual object changes every slide without one clear system.
- The hidden flaw is missing.
- The post teaches tips but no mental model.
- The paid bridge feels like bait.
- The post uses income claims, fake urgency, or generic hustle language.
- The idea attracts prompt collectors rather than serious operators.

## Final approval scorecard
Score each item from 0 to 2.

| Criterion | 0 | 1 | 2 | Score |
| --- | --- | --- | --- | --- |
| Operator problem | Vague | Somewhat specific | Sharp and recognizable | TBD |
| Hidden thinking flaw | Missing | Present but soft | Clear and diagnostic | TBD |
| Mental model | Generic | Useful but common | Reusable and differentiated | TBD |
| Central visual object | Decorative | Relevant but weak | Carries the explanation | TBD |
| Low-text execution | Text-heavy | Mixed | Clean and scannable | TBD |
| Tool-secondary discipline | Tool-led | Tool mentioned too early | Tool clearly secondary | TBD |
| Paid bridge | Confusing or bait-like | Somewhat clear | Optional and implementation-led | TBD |

## Approval rule
- **12-14:** Approve for design.
- **9-11:** Rework before design.
- **0-8:** Reject or reframe.
