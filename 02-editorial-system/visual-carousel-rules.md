# Visual Carousel Rules

## Purpose of this file
Use this file to keep carousels infographic-led, low-text, and visual-first.

## Carousel standard
Every carousel must have one central visual object. The visual must explain the idea, not decorate the slide.

## Acceptable central visual objects
- Decision tree
- Control panel
- Evidence bank
- Proof stack
- Narrative spine
- Operating map
- Scorecard
- Ladder
- Funnel
- Loop
- Before/after system
- Teardown map

## Slide-level rules
- One idea per slide.
- One visual relationship per slide.
- Minimal slide text.
- Use labels instead of paragraphs.
- Use arrows, sections, contrast, and hierarchy to show logic.
- Do not make the slide depend on a long caption to be understood.
- Make the carousel useful enough to save.
- Keep the design calm, sharp, and operator-grade.

## Required carousel brief fields
1. Audience problem
2. Hidden thinking flaw
3. Mental model
4. Central visual object
5. Slide-by-slide visual sequence
6. Minimal slide text
7. Paid asset bridge, if relevant

## Visual quality test
Before approving a carousel, ask:

1. What is the central visual object?
2. What does the visual explain that plain text would not?
3. Can the reader understand the logic by scanning the slides?
4. Is there one clear visual hierarchy?
5. Does the carousel feel like an operating diagram rather than a social media listicle?

## Reject or rework if
- The slides are mostly paragraphs.
- The visual is decorative.
- The carousel uses random AI icons as the hook.
- The post is just a list with design around it.
- The central object changes every slide with no coherent system.
