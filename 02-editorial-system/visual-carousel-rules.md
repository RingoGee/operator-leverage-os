# Visual Carousel Rules

## Purpose of this file
Use this file to keep carousels visual, analytical, and argument-led.

This file follows the higher standard in `02-editorial-system/thought-leadership-doctrine.md`. The goal is not to create generic low-text infographics. The goal is to create visual strategy memos that help operators understand a problem, see the mechanism, and change behavior.

## Carousel standard
One carousel should have one central argument, but it may use multiple visual moves to develop that argument.

Do not over-enforce one repeated visual object across all slides. A repeated object is useful only when each repetition reveals a new layer of reasoning.

The visual system must explain the idea, not decorate the slide.

## Approved visual moves
Use one or more of these visual moves when they serve the argument:

- Tension visual
- First-principles / root-cause map
- Evidence card
- Antithesis comparison
- Mechanism diagram
- Framework model
- Applied example
- Decision tool
- Behavior checklist
- Profile-entry slide

## Slide-level rules
- One idea per slide.
- One clear purpose per slide.
- Each slide must advance the argument.
- Each slide must create a reason to swipe.
- Use visual hierarchy, sections, arrows, annotations, contrast, and labels to show logic.
- Use structured high-signal text instead of forcing ultra-minimal copy.
- More text is acceptable when it creates context, contrast, evidence, examples, decision logic, or interpretive clarity.
- Avoid paragraph blobs, generic advice, and decorative buzzwords.
- Do not make the slide depend on a long caption to be understood.
- Make the carousel useful enough to save or share.
- Keep the design calm, sharp, analytical, and operator-grade.

## No redundant visuals
A visual cannot simply mimic the headline.

Reject a slide if the visual:

- Repeats the headline without adding analysis.
- Restates the previous slide in a new layout.
- Uses the same object with only different wording.
- Looks premium but does not reveal structure, causality, contrast, decision logic, or value leakage.

## Required carousel brief fields
1. Audience problem
2. First-principles cause
3. Evidence / data / example, where relevant
4. Common false solution
5. Antithesis
6. Hidden mechanism
7. Mental model or framework
8. Visual argument path
9. Slide-by-slide visual sequence
10. Structured slide text
11. Primary action objective
12. Behavior shift
13. Profile-entry reason
14. Paid asset bridge, if relevant

## Slide usefulness test
Every slide must pass this question:

> What does this slide make the reader understand that the previous slide did not?

If the answer is unclear, reject or redesign the slide.

## Visual quality test
Before approving a carousel, ask:

1. What is the central argument?
2. What visual moves develop that argument?
3. What does each visual explain that plain text would not?
4. Can the reader understand the logic by scanning the slides?
5. Does each slide add a new layer of understanding?
6. Is the text structured and useful rather than merely minimal?
7. Does the carousel feel like a visual strategy memo rather than a social media listicle?

## Reject or rework if
- The slides are mostly unstructured paragraphs.
- The visual is decorative.
- The carousel uses random AI icons as the hook.
- The post is just a list with design around it.
- The same visual repeats without revealing new reasoning.
- The visual changes every slide with no coherent argument path.
- The hook summarizes the answer instead of creating tension.
- The final slide has no behavior shift or profile-entry reason.
