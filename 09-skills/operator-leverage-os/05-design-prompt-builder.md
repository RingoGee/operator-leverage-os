# OLS Design Prompt Builder

## Purpose
Convert an approved production draft into a design prompt direction file for Operator Leverage OS visual creation.

## When to use
Use after a production draft is approved and the user wants design-ready visual direction.

## Inputs required
- Approved production draft
- Optional visual style notes
- Optional prior generation feedback

## Source files to read
- Selected production draft in `07-exports/carousel-production-drafts/`
- `01-brand-foundation/visual-identity.md`
- `02-editorial-system/visual-carousel-rules.md`
- `03-carousel-system/visual-object-bank.md`
- `03-carousel-system/carousel-quality-checklist.md`

## Output files to create or update
- `07-exports/design-prompts/[number-topic-slug-design-prompts].md`

Design prompt file must include:

- Overall visual direction
- Premium analytical identity
- Locked slide chrome system
- Visual identity direction
- Signature accent palette
- Typography direction
- Mobile readability rules
- Slide-by-slide visual directions
- Composition archetype per slide
- Dominant element per slide
- Headline mode per slide
- Signature visual grammar per slide
- Evidence slide direction
- Antithesis slide direction
- Framework slide direction
- Application slide direction
- Final profile-entry slide direction
- What to avoid
- Design QA checklist

## Step-by-step procedure
1. Read production draft and visual system rules.
2. Convert slide production notes into design instructions.
3. Add locked chrome and brand grammar.
4. Add mobile-first layout guidance.
5. Specify where visuals should dominate over headlines.
6. Assign signature visual devices meaningfully.
7. Add avoid rules.
8. Save Markdown design prompt.

## Guardrails
- Do not create images.
- Do not create Canva files.
- Do not create visual execution pack unless asked.
- Do not invent brand visuals outside the approved visual identity.
- Do not make visuals decorative.
- Do not use generic SaaS/MBA/AI-tool aesthetics.
- Do not create final designed slides.

## Done when
- Design prompt file is complete.
- It is ready for visual execution pack creation.
- It preserves argument, hierarchy, and visual discipline.

## Summary format
1. File created
2. Design system choices
3. Slide-level visual logic
4. Chrome/signature grammar notes
5. Readiness for visual execution pack
6. Confirmation of no out-of-scope work

## Brand Identity Lock v1 requirements
Every design prompt must include a dedicated Brand Identity Lock v1 block.

That block must specify:

- Palette: Warm Ivory / Soft Paper White, Deep Charcoal / Near Black, Dark Forest Green, Slate Blue, Proof Orange / Controlled Amber, Muted Red / Rust, and Deep Green.
- Typography: display serif for major conceptual headlines; clean modern sans-serif for body, labels, diagrams, notes, and source lines; optional mono-style only for small source tags, memo codes, or field-manual markers.
- Chrome: stable top-left series/channel label, top-right slide number, optional memo/category label, bottom-left Operator Leverage OS mark, optional footer source/caveat line, consistent safe margins, and baseline alignment.
- Spacing: generous margins, clear separation between headline/explanation/visual object, mobile-first sizing, and no unreadable tiny labels.
- Diagram language: clean line diagrams, restrained icons, consistent line weights, structured cards/panels, purposeful arrows, before/after comparisons, evidence cards, decision gates, and proof trails.
- Surface treatment: warm paper-like background, subtle texture only, soft minimal shadows, and meaningful stamps/labels/manual marks only.
- Allowed variation: slide archetype, visual metaphor, framework depth, information density, evidence treatment, diagram type, headline tone, or single-post accent emphasis.

Design prompts must not invent new visual identities. Vary composition, not identity.

Final QA:

- Does this feel like the same publication as other Operator Leverage OS posts, while still having a distinct argument?
- Would a reader recognize the brand without every carousel using the same template?

## Free Value Per Slide design requirements
Design prompts must organize useful density elegantly.

Every design prompt must specify how layout supports reader value, not just visual polish.

The visual object must teach, diagnose, clarify, compare, filter, rewrite, or help the reader decide.

Design prompts must preserve:

- simple but informative language;
- plain-language shadows;
- practical takeaway visibility;
- one dominant takeaway per dense slide;
- useful density without clutter.

## Mobile readability and narrative continuity requirements
Every design prompt must specify minimum practical text readability for Instagram mobile.

Design prompts must include:

- **Minimum mobile readability:** all essential text readable without zoom.
- **No essential microcopy:** tiny text may support, but never carry, meaning.
- **Four-level text hierarchy:** Level 1 headline, Level 2 support, Level 3 framework/diagram labels, Level 4 optional source/chrome.
- **Readable diagram labels:** all diagram labels large enough for phone viewing.
- **Repeated visual motifs:** visual continuity devices that support the narrative thread.
- **Reader question chain:** the question each slide answers.
- **Previous slide connection:** how each slide advances the prior slide.
- **Reader question created:** what question the next slide should answer.
- **Next slide handoff:** the visual or verbal cue into the next slide.
- **Transition risk:** where flow may feel abrupt.
- **Mobile readability risk:** what could become too small or dense.
- **Smallest meaningful text risk:** any label that must remain readable.

## Design continuity guardrails
- Slides should vary in archetype without feeling visually unrelated.
- Preserve Brand Identity Lock v1.
- Maintain consistent chrome, palette, typography, and spacing.
- Use repeated motifs across the deck where useful.
- If Slide 6 introduces the core framework, Slides 1–5 should visually prepare the reader for it.
- Dense slides should use fewer larger blocks, not many tiny fragments.

## Required final design checks
- Can the reader follow the carousel without feeling reset at every slide?
- Does each slide make the next slide feel necessary?
- Is every meaningful text element readable on Instagram mobile?
- Are small labels supportive rather than essential?
- Does the carousel feel like one guided argument?
