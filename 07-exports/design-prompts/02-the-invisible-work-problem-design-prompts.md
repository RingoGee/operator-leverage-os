# Design Prompt Direction: The Invisible Work Problem

## Purpose
This file gives visual direction for the redesigned first carousel system. It is not a designed slide file, Canva file, image file, or final artwork.

The carousel should feel like a premium analytical memo for operators whose work needs to be seen, remembered, and reused.

## Overall visual direction
Design this carousel as a visual strategy memo, not a generic infographic carousel.

The central argument:

> Useful work does not disappear because it is small. It disappears because it is not converted into proof.

Slide 1 should express this with sharper stopping power: the work that gets remembered is not always the work that mattered most; it is the work that became proof.

The visual system should show how work loses value when it is not captured, connected to outcomes, verified by signals, stored as proof, and reused for leverage.

Use different visual moves across slides:

- Tension visual
- Root-cause map
- Evidence card / mini-case
- Antithesis table
- Leakage map / waterfall
- Funnel model
- Worked example / proof trail
- Behavior checklist / profile-entry slide

## Premium analytical identity
The carousel should feel like:

- A strategic field manual.
- A high-signal operator memo.
- A premium analytical system.
- A visual operating manual.
- A compressed strategy memo with diagrams.

It should not feel like:

- A generic SaaS carousel.
- A first-year MBA class template.
- A productivity-hack page.
- A motivational page.
- An AI tools account.
- A stock corporate infographic.

## Visual grammar
Use recurring visual grammar from the thought leadership doctrine:

- Leakage points
- Decision gates
- Proof stamps
- Evidence cards
- Antithesis tables
- Root-cause maps
- Operator notes
- Side annotations
- “So what?” callouts
- Memory decay
- Proof trails
- Signal vs noise zones

Use structured text. Do not over-optimize for ultra-minimal text. The text should feel organized, useful, and analytical.

## Slide-by-slide visual directions
### Slide 1: Tension / question
- **Visual direction:** Show the gap between work that mattered and work that got remembered.
- **Layout:** Split field. Left side shows meaningful work artifacts; right side shows the smaller subset that became proof and reached stakeholder memory.
- **Key visual cue:** Remembered work is the work that became proof.
- **Text hierarchy:** Large status-threat headline, one tension line, one small annotation.
- **Avoid:** Generic laptop illustration, motivational quote, or full funnel reveal.

### Slide 2: First-principles diagnosis
- **Visual direction:** Root-cause map showing why useful work gets missed.
- **Layout:** Top node: “Useful work gets missed.” Four cause nodes below: weak memory, limited attention, scattered context, no reusable proof trail.
- **Key visual cue:** Multiple structural causes feeding into invisibility.
- **Text hierarchy:** Diagnosis headline plus compact cause labels.
- **Avoid:** Blaming managers or turning the slide into a complaint list.

### Slide 3: Evidence / data / example
- **Visual direction:** Evidence card using example-based evidence.
- **Layout:** Two mini-case cards side by side: “Memory-based review” vs “Proof-trail review.”
- **Key visual cue:** Same work, different evaluability.
- **Required label:** “Example-based evidence, not a sourced statistic.”
- **Avoid:** Invented numbers, “studies show,” or unrelated statistics.

### Slide 4: Antithesis / contrast
- **Visual direction:** Antithesis table comparing default operator behavior with high-leverage operator behavior.
- **Layout:** Two-column table. Keep rows aligned and easy to scan.
- **Key visual cue:** Right side should feel like an upgrade path, not a judgment.
- **Suggested contrast labels:** Memory → evidence trail; activity → outcome; review season → weekly capture; claim → before/after change; interpretation → reusable proof.
- **Avoid:** Harsh language, shaming, or too many comparison rows.

### Slide 5: Hidden mechanism
- **Visual direction:** Leakage map or waterfall showing proof conversion failure points.
- **Layout:** Descending path from “Work done” to “Low remembered value.” Add leakage points at capture, connection, verification, storage, and reuse.
- **Key visual cue:** Work loses value at every broken conversion point.
- **Text hierarchy:** Mechanism headline, short leak labels, small “so what?” callout.
- **Avoid:** A simple linear arrow with no visible value loss.

### Slide 6: Framework or decision tool
- **Visual direction:** The Proof Conversion Funnel.
- **Layout:** Funnel or staged conversion system with six stages: Work done, Captured, Connected to outcome, Verified by signal, Stored as proof, Reused for leverage.
- **Key visual cue:** Proof quality increases as work moves through the funnel.
- **Add stage questions:** What moved? Where is it recorded? What outcome changed? What signal supports it? Where can it be retrieved? Where will it create leverage?
- **Reuse annotation:** Reused in weekly updates, stakeholder reviews, appraisal narratives, decision memos, handoffs, and case studies.
- **Avoid:** Making it look like a sales funnel or reducing it to a generic three-step chain.

### Slide 7: Application / worked example
- **Visual direction:** Before/after update plus proof trail.
- **Layout:** Left panel: weak weekly update. Right panel: proof-converted stakeholder update with highlighted components. Bottom strip: note → artifact → signal → update → review.
- **Key visual cue:** The same work becomes more useful when proof is attached and reused in a review moment.
- **Text hierarchy:** Clear before/after labels with highlighted proof elements.
- **Avoid:** Invented metrics, inflated impact language, or AI tool references.

### Slide 8: Behavior shift + profile reason
- **Visual direction:** Memo-style behavior checklist and profile-entry slide.
- **Layout:** Central operating question, five small checklist items, one low-pressure profile-entry line.
- **Key visual cue:** The reader leaves with a weekly operating habit.
- **Profile-entry line:** “More operator leverage systems for people turning invisible work into visible proof.”
- **Avoid:** Hard selling, payment references, product CTA, or generic “save this” ending only.

## Evidence slide direction
The evidence slide must be clearly marked as example-based evidence.

Use the example to show that the same work becomes easier to remember, evaluate, and advocate for when it has a proof trail.

Do not add a statistic unless a credible source is later provided and cited. The slide should build trust by being honest about the evidence type.

## Antithesis slide direction
The antithesis slide should show behavior contrast without insulting the audience.

Use labels like:

- Default operator
- High-leverage operator

Avoid labels like:

- Lazy operator
- Bad operator
- Amateur operator

The goal is to make the reader feel, “I can upgrade how I communicate my work,” not “I am being attacked.”

## Framework slide direction
The framework slide should make the Proof Conversion Funnel feel practical and memorable.

Use the six-stage model:

1. Work done
2. Captured
3. Connected to outcome
4. Verified by signal
5. Stored as proof
6. Reused for leverage

The funnel should communicate that value leaks when stages are skipped and leverage increases when proof is reusable. Keep the reuse layer concrete: weekly updates, stakeholder reviews, appraisal narratives, decision memos, handoffs, and case studies.

## Application slide direction
The application slide should show how proof conversion changes an actual weekly stakeholder update.

Do not create fake results. Use a qualitative before/after:

- Weak: “Worked on reducing customer escalations this week.”
- Stronger: “Reduced repeat escalation risk by identifying the top 3 recurring handoff gaps, aligning support and product on ownership, closing 2 process gaps, and capturing before/after escalation signals for next week’s review.”

Highlight the structure inside the stronger update:

- Risk or problem
- Actions taken
- Ownership alignment
- Process gaps closed
- Signal

## Final profile-entry slide direction
The final slide must combine behavior shift and profile-entry reason.

The core behavior shift:

> Before your next update, ask: what proof did this work create?

The profile-entry reason:

> More operator leverage systems for people turning invisible work into visible proof.

Keep the tone calm and category-led. If a future bridge is included, it should be a small optional note, not the main CTA.

## What to avoid
- Do not create images or final slide designs in this file.
- Do not create a Canva file.
- Do not use generic SaaS gradients or random AI icons.
- Do not use a single repeated visual object on every slide unless it reveals new reasoning.
- Do not make visuals repeat the headline.
- Do not make the carousel feel like a productivity hack.
- Do not use invented statistics.
- Do not add prompt dumps or AI tool lists.
- Do not hard-sell Proof Stack.
- Do not add payment links, product pages, dashboards, scripts, charts, integrations, or automation workflows.
